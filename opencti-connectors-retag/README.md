## Overview

If a broken version is released, every `opencti/connector-*` image on Docker
Hub must have its `latest` tag rollback to a previous version.  
This script automates that process by:

1. Authenticating to Docker Hub and listing every `connector-*` repository
   under the `opencti` namespace.
2. For each repository, fetching the manifest of `<version>` directly from the
   Docker Registry API.
3. Writing that same manifest under the `latest` tag — an instant, zero-bandwidth
   operation (no image layers are transferred).

---

## How it works

```
Docker Hub API v2          →  login + list all opencti/connector-* repos
Docker Registry API v2     →  GET  manifest of <image>:<version>
                              PUT  manifest as  <image>:latest
```

Re-tagging is a **manifest copy**: only a few kilobytes of JSON are exchanged.
No image layers are downloaded or uploaded.  
Multi-architecture images (manifest lists / OCI indexes) are fully supported —
the manifest type is preserved verbatim.

## Usage

### Basic

```bash
python opencti_connectors_retag.py \
  --username myuser \
  --password myPAT \
  --version 7.260309.0
```

### All options

```
usage: opencti_connectors_retag.py
       [-h] --version VERSION [--username USERNAME] [--password PASSWORD]
       [--password-stdin] [--dry-run]
       [--include REPO [REPO ...]] [--exclude REPO [REPO ...]]
       [--workers N]

options:
  -h, --help                    Show this help message and exit

required:
  --version VERSION, -v VERSION
                                Already-published version tag to promote to
                                latest (e.g. 7.260309.0)

authentication:
  --username USERNAME, -u USERNAME
                                Docker Hub username
                                (or set DOCKER_USERNAME env var)
  --password PASSWORD, -p PASSWORD
                                Docker Hub password or Personal Access Token
                                (or set DOCKER_PASSWORD env var)
  --password-stdin              Read the password from stdin (recommended
                                in scripts — avoids shell history exposure)

behaviour:
  --dry-run                     Simulate the run: check which tags exist,
                                print what would happen, make no changes
  --include REPO [REPO ...]     Only process the listed connector names
                                (e.g. connector-misp connector-cve)
  --exclude REPO [REPO ...]     Skip the listed connector names
  --workers N                   Number of parallel threads (default: 8)
```

### Examples

```bash
# ── Recommended: credentials via environment variables ──────────────────────
export DOCKER_USERNAME=myuser
export DOCKER_PASSWORD=myPAT   # use a Docker Hub Personal Access Token

python opencti_connectors_retag.py --version 7.260309.0


# ── Dry-run first — no writes, just check which tags exist ──────────────────
python opencti_connectors_retag.py --version 7.260309.0 --dry-run


# ── Promote only specific connectors ───────────────────────────────────────
python opencti_connectors_retag.py --version 7.260309.0 \
  --include connector-misp connector-cve connector-mitre


# ── Skip deprecated or unrelated connectors ────────────────────────────────
python opencti_connectors_retag.py --version 7.260309.0 \
  --exclude connector-amitt connector-history


# ── Read password from stdin (CI-safe) ─────────────────────────────────────
echo "$DOCKER_PASSWORD" | python opencti_connectors_retag.py \
  --version 7.260309.0 --username myuser --password-stdin


# ── Increase parallelism for large connector sets ──────────────────────────
python opencti_connectors_retag.py --version 7.260309.0 --workers 16
```

## Credentials & security

| Method | How |
|---|---|
| **Environment variables** *(recommended)* | `DOCKER_USERNAME` / `DOCKER_PASSWORD` |
| **`--password-stdin`** | `echo "$PAT" \| python script.py --password-stdin` |
| **Interactive prompt** | Leave `--password` unset — the script will prompt securely |
| **`--password` flag** | Convenient but visible in shell history — avoid in CI |

> **Use a Personal Access Token (PAT)** with the minimum required scope
> (`Read & Write` on the `opencti` namespace) rather than your Docker Hub
> account password.  
> Generate one at **Hub → Account Settings → Security → New Access Token**.

| Icon | Status | Meaning |

| ✅ | `ok` | `latest` successfully updated |
| ⏭️ | `skipped` | The requested version tag does not exist for this image |
| 🔍 | `dry-run` | Would have been retagged (dry-run mode) |
| ❌ | `error` | API error — details printed inline and in the summary |

### Exit codes

| Code | Meaning |
|---|---|
| `0` | All connectors processed successfully (skips are not failures) |
| `1` | One or more connectors encountered an error |

## CI/CD integration

### GitHub Actions

```yaml
name: Promote connector latest tag

on:
  workflow_dispatch:
    inputs:
      version:
        description: "Version to promote to latest (e.g. 7.260309.0)"
        required: true

jobs:
  retag:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: pip install requests

      - name: Dry-run check
        env:
          DOCKER_USERNAME: ${{ secrets.DOCKER_USERNAME }}
          DOCKER_PASSWORD: ${{ secrets.DOCKER_PASSWORD }}
        run: |
          python opencti_connectors_retag.py \
            --version ${{ inputs.version }} \
            --dry-run

      - name: Promote to latest
        env:
          DOCKER_USERNAME: ${{ secrets.DOCKER_USERNAME }}
          DOCKER_PASSWORD: ${{ secrets.DOCKER_PASSWORD }}
        run: |
          python opencti_connectors_retag.py \
            --version ${{ inputs.version }}
```

> Store `DOCKER_USERNAME` and `DOCKER_PASSWORD` as **GitHub Actions secrets**
> (repository or organisation level).

## Limitations

| Limitation | Detail |
|---|---|
| **Docker Hub rate limits** | The script makes one manifest GET + one manifest PUT per connector. With ~90 connectors this is well within Hub's API limits. |
| **Write permissions required** | The authenticated user must have push access to every `opencti/connector-*` repository. |
| **Version must pre-exist** | The script promotes an existing tag — it does not build or push new images. Connectors where the version tag is absent are silently skipped. |
| **Hub API pagination** | Repositories are fetched 100 per page. Namespaces with > 1 000 repos may need pagination tuning (unlikely for `opencti`). |
